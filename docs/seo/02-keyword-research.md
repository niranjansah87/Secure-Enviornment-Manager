## 3. Opportunity Scoring Methodology

Because live proprietary third-party tool search volumes (Ahrefs, Semrush) are third-party estimates, we apply a transparent **Business Opportunity Score (BOS)** formula based on verifiable technical factors:

$$\text{BOS} = (\text{Relevance} \times 0.40) + (\text{Conversion Intent} \times 0.35) + (\text{Ranking Feasibility} \times 0.25)$$

*   **Relevance (1–10):** Direct architectural alignment with SEM features.
*   **Conversion Intent (1–10):** Likelihood of the user cloning the repo, installing CLI, or deploying the Docker container.
*   **Ranking Feasibility (1–10):** Lack of entrenched mega-enterprise monopoly on exact long-tail phrasing.

## 5. Cannibalization & Content Gap Analysis

1.  **Resolved Cannibalization Risk:** Previously, because `/docs` had no independent metadata, search engines evaluated `/` and `/docs` under the same title tag, splitting topical authority.
    *   *Remedy:* Strict separation. `/` is the primary commercial landing page targeting "self-hosted secrets manager", "open-source alternative", and "environment variable sync". `/docs` is the technical authority hub targeting cryptographic algorithms, CLI syntax, and API endpoints.
2.  **Identified Content Gaps:**
    *   Lack of explicit step-by-step CI/CD code snippets on the homepage (addressed in terminal component).
    *   Absence of a Dedicated FAQ schema on `/docs` addressing key migration concerns (e.g., migrating from Doppler or HashiCorp Vault).
